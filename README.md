# 비판루프 멀티에이전트 팀 vs 단일 LLM — 조건민감 화학설계 대조실험

연세대 AX 캠프 트랙1(AI 연구 에이전트) 4주차 산출물. 앵커 논문 *The Virtual Lab*이 고정된 전제로 취급한 "팀이 비판루프를 거쳐 논의한다"는 조건을 조작변수로 이분화하고, 조건민감 화학설계 과제 20건에서 대조실험을 수행한 기록 전체다.

## 핵심 결과

LLM-judge 루브릭에서는 팀(조건B)이 20건 중 18건에서 우위를 보였다(Wilcoxon 정규근사 p=0.00019, Cohen's dz=1.61). 그러나 네 가지 결과가 이 우위의 해석을 제한했다.

| 관찰 | 수치 |
|---|---|
| 블라인딩 실패 | 판정자가 20/20 전부 조건B를 정확히 식별 (이항검정 p=1.9e-6) |
| 격차의 항목 편중 | 안전성 항목 +2.100 vs 나머지 세 항목 +0.700~0.875 |
| 문헌일치 지표에서 차이 소멸 | 조건A 30/32(93.8%) vs 조건B 29/32(90.6%), 격차 −0.125 |
| H2 방향 반전 | 조건민감도 k에 대한 회귀 기울기 −0.266 (p=0.011), 어려운 과제일수록 격차 축소 |

안전성 항목을 제외한 강건성 검정에서도 H1은 유지되고 H2는 여전히 반전됐다(격차 0.792, p=0.0057, dz=0.906, 기울기 −0.338).

결론은 "팀이 더 낫다"가 아니다. **웻랩 검증 없이 LLM-judge 점수만으로 멀티에이전트 구조의 우월성을 주장하는 평가 설계는, 실제 과학적 정확성이 아니라 응답의 포괄성과 상세함을 측정하고 있을 가능성이 있다.**

## 실험 설계 요약

- 과제 20건을 조건민감도 k=1~5로 층화(각 4건)
- **조건A(단일 LLM)**: 토론 없이 1회 호출
- **조건B(비판루프 팀)**: 서로 다른 에이전트 7회 호출 — 합성화학자 초안 → Critic 비판 → 메커니즘 전문가 개선 → Critic 비판 → 공정안전 전문가 최종개선 → Critic 비판 → PI 통합
- 총 180회 실제 호출. 셀프시뮬레이션 프록시는 사용하지 않았다.
- 기반 모델은 Claude 계열 단일 모델(세션 상속 방식)

## lab_app 실행

```bash
cd lab_app
pip install -r requirements.txt
python3 app.py
# http://127.0.0.1:5050
```

캐릭터 스프라이트와 바닥 타일은 Kenney(kenney.nl)의 CC0 에셋을 사용했다.

## 재현성에 관한 정직한 고지

- 멀티에이전트 실행 엔진은 독립 API 스크립트가 아니라 Claude Code의 에이전트/워크플로우 도구로 구동했다. 방법론상 "Claude 기반, 세션 상속" 방식이며 논문에도 그대로 명시했다.
- 실험실이 없어 설계된 조건으로 실제 합성을 검증하지 못했다. 주장 범위는 설계의 논리적 타당성(design plausibility)에 한정된다.
- 실행 과정에서 겪은 실패(세션 사용량 한도로 2회 완주 실패, 배치 필터 결함, 빈 응답이 다음 단계로 전파된 데이터 손상)는 논문 3.4절과 `RESUME_HERE.md`에 축소 없이 기록했다.
- 참고문헌의 서지 정보(권·호·페이지)는 원문 대조가 아직 필요하다.
